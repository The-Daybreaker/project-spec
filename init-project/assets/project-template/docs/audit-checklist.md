# 审计清单（audit-checklist.md）

> 用途：实施完成后的自动审计。**自审**（实施者逐项核对）与**独立审计**
> （独立子 agent / 独立会话，只看 `git diff` 与本清单，不共享实施者上下文）
> 共用本清单。审计人逐项标注 ✅ / ❌ / N/A，❌ 必须附说明并修复。
> 独立审计时：不要看实施者的结论，只按本清单审查 diff 与仓库状态。

## 1. 需求与计划对齐

- [ ] 需求已复述，方案要点已列明，且获得用户明确确认（红线：未确认不实施）
- [ ] 涉及**立项类话题**（项目思路/需求/架构/功能/产品）时，已在 GitHub 调研现成
      参考并提醒用户「先调研再立项」（红线 13）
- [ ] 本次改动范围与确认的方案一致（没有夹带未确认的改动）
- [ ] 涉及高风险操作（破坏性变更、永久删除、发布/推送）时已征得同意

## 2. 实现正确性

- [ ] 改动符合项目设计（`private/dev/DESIGN.md`）与代码规范
- [ ] 边界情况与错误处理已考虑（输入校验、失败路径、回退）
- [ ] 无死代码/调试残留（console.log、TODO 之外的无用代码）
- [ ] 无重复实现（复用已有能力，未重复造轮子）
- [ ] 无意外删除或误改与本次需求无关的内容（diff 中无「路过修改」）

## 3. 文档同步（改动完成即文档就绪）

- [ ] `private/dev/CHANGELOG.md` 已新增/更新本次条目
- [ ] `private/dev/DESIGN.md` 已同步（若设计/流程有变化）
- [ ] `private/dev/TEST-REPORT.md` 已记录验证结果
- [ ] `private/dev/WORKLOG.md` 已按阶段更新（阶段落盘，红线 14）
- [ ] 发现过时内容已立即修复（不论是否本轮引入）；无变更时状态文档（WORKLOG）也已校准
- [ ] 本轮候选经验已完整写入 `EXPERIENCE-TO-TEMPLATE.md` / `EXPERIENCE-TO-KB.md`
      （如有；沉淀时以该文档为唯一依据）
- [ ] 根 `AGENTS.md` / `private/AGENTS.md` 已同步（若入口/状态/流程有变化）
- [ ] `README.md` / `docs/`（DOCS / audit-checklist / UPGRADE / CONTRIBUTING 等）已同步
      （若用户视角有变化）
- [ ] **经验沉淀已提醒**：本次为架构变化或更新（发布）时，已提醒用户沉淀经验
      （知识库沉淀 + 可复用经验集成进项目模板，由用户决定是否执行）

## 4. 红线合规

- [ ] 未实施前已确认（第 1 节）；删除均走可恢复路径
- [ ] 对话内删除已先移入 `_trash/<agent产品名>_<日期>_<时分>/`（如
      `codex_2026-08-25_2330`），任务结束时整体进回收站
      （如有删除）
- [ ] 上下文压缩/新对话后已重读红线规范与相关文档（红线 15）
- [ ] 重要写入已回读校验
- [ ] 创建前做过相似检查（无重复文件/内容）
- [ ] 未破坏用户未提交的改动；无对共享分支的 force push
- [ ] `private/` 外无个人/机器专属信息；主仓库未包含 `private/` 内容
- [ ] 无密钥/凭据入库（搜索 `.env`、`key`、`token`、`password` 等字样于 diff）

## 5. 测试与验证

- [ ] 检查命令（`scripts/ci_check.py`）通过
- [ ] 项目测试通过，结果已记录（或「用户确认沿用」且已注明）
- [ ] 新增功能有对应测试/验证记录

## 6. 版本与发布就绪

- [ ] `version.json` 的 `version` 与 `private/dev/CHANGELOG.md` 顶部版本一致，递增规则正确
- [ ] `git -C private status --short` 干净（private 子 git 已同步，或本次无私有变动）
- [ ] 主仓库 `git status` 只含公开区（A 区）文件
- [ ] 提交信息符合格式（普通提交不带版本号，发布提交带 vX.Y.Z）；tag / Release
      计划明确
- [ ] `version.json` 的 `template_version` 与当前模板版本一致（初始化后/升级后）

## 7. 文档无缝衔接（冷启动新人视角；大版本后/跨会话前执行，每轮对话顺手查）

- [ ] 状态最新：WORKLOG「当前做到哪里」精确到最后一步，并给出「下次从这里继续」
- [ ] WORKLOG 生命周期合规：「当前任务」已切换为新任务；阶段记录硬事实
      （文件数/版本/提交）与仓库实际一致；旧任务完结已归档（清理先询问用户）
- [ ] 指引可执行：新人对着一句话能不猜就动手
- [ ] 硬事实不过时：红线条数、版本号、提交链、页签数等已 Grep 全局核实
- [ ] 单一真相：同一信息只有一处维护，其余为链接引用
- [ ] 文档治理合规：决策正文无历史标注/旧段落残留；AI 未在正文追加历史说明；
      确需留痕仅在 CHANGELOG 一行
- [ ] 方法：先 Grep 交叉核实硬事实，再逐段读；修复后整篇回读复核

## 8. 变更分级与质量门禁

| 级别 | 适用 | 门禁 |
|---|---|---|
| 文档/文案类 | 纯文档改动 | 改完自查即可 |
| 常规代码 | 一般功能/修复 | `python -m py_compile` + 关键写入回读校验 |
| 架构/红线/范围类 | 触及定案清单/红线/大范围重构 | 先询问人类 + 独立审计，P0/P1 问题清零才合入 |
