# 通用项目模板

这是一套面向「人 + AI 助手协作」的通用项目模板，分两层：**框架**是每个
项目都一样的固定骨架——冷启动链、任务板、AI 助手记忆、git 约定，
保证项目什么都不配也能最低限度运转；**spec** 是具体工作流的
声明式编排（一份 `spec.md` + 产出骨架 `assets/`），需要时按需从云端货架
拉取、拉下来自由改，不装 spec 就以框架形态轻装运转。根目录 `AGENTS.md` 是协作总纲，本文件是它的精简辅助手册。

## 写给用户

> 由于现有Agent的能力不足，很多规范写进AGENTS.md也无法保证执行，因此这里写一些面向用户的提醒，由用户来把关。

1. **使用正向提示词**：除非是在给AI设定规范，否则最好不要使用“不要xxx”这样的提示词，因为从现有大模型的表现来看，越是强调不要，模型越会记住，并且会把“不要xxx”直接写进文档内，污染上下文。因此最好采用正向描述，“把xxx改为xxx”、“只需要xxx”。
2. **信息安全**：在项目发布到公开渠道之前，最好让Agent审计一下项目内是否有隐私文件，AI总是会把各种信息写进文档、代码内部，为了防止信息泄露，最好也人工复核一下各个文档。
3. **压缩重读：** 在触发上下文压缩后，很可能丢失上下文原有的规范要求等信息，因此在发现触发上下文压缩后，请及时提醒AI重读AGENTS.md，也可以在agent内设置钩子。
4. **对话关闭落盘:** 虽然模板中规定AI及时更新task，但是很难保证绝对遵循，因此在决定关闭一个对话时，请提醒AI更新task并确保冷启动无缝衔接。

## 快速开始

1. **初始化**：让 AI 用 init-project 技能把模板复制到目标目录（自动
   排除 `_trash/`、`.git/`、`__pycache__/`，已有文件只跳过、不覆盖），
   也可以手动复制模板内容；
2. **首次对话**：AI 会先读根 `AGENTS.md` 完成冷启动，这时和它对齐项目
   背景与目标；需要具体工作流时按 `spec/AGENTS.md` 的指引选装 spec——
   浏览云端 `specs/` 选货、clone 云端仓、把 `spec.md` + `assets/` 复制进
   `spec/<id>/`，之后这份 spec 归你自由改；
3. **没有现成 spec**：把云端 `build/` 构建规则拉到 `spec/build/`，按
   `spec/build/build.md` 和 `spec-template/` 母版自己写一份 `spec.md`。

## 目录速览

| 目录 | 放什么 |
| --- | --- |
| `spec/` | 出厂只有机制说明书 `AGENTS.md`（讲 spec 是什么、怎么拉、怎么读）；spec 内容与构建规则按需从云端货架拉取 |
| `context/` | 项目上下文文档（PRD / ADR / 知识库等），装什么、骨架由 spec 决定，没有 spec 时为空 |
| `process/` | 协作的活状态区：常驻的 `task.md` 任务板、`memory.md` 助手记忆，以及笔记 / review 验收件等临时件（用完即清） |
| `workspace/` | 干活主工作区：`source/` 源产物 + `delivery/` 交付物 |
| `logs/` | 已结束、有留存价值的历史归档（只追加），如 memory 失效条目、讨论记录、阶段归档 |

## 协作协议速览

新会话冷启动按固定顺序「读盘」：根 `AGENTS.md`（目录地图、会话协议、
宪章 6 条）→ 通读 `process/` 全部文件（`task.md` 进行中 / 下一步 / 阻塞、
`memory.md` 助手记忆，以及笔记 / review 等临时件）；装了 spec 的项目再读
`spec/<id>/spec.md` 判定入口、走阶段。
完整条款以根 `AGENTS.md` 为单一事实源。
