# MODULE.md — 愿景与排期（模块规范）

> **适用范围**：当 agent 负责维护本模块的产出`context/vision.md` 时，加载并遵循本文件。项目级总纲见仓库根 `AGENTS.md`。
> 
> 本文件是「愿景与排期」模块自带的 agent 规范，随模块例化、随模块停用。

## 一、产物目录与例化

本模块的全部产物只落在 `context/` 下，一个文件：

```
context/vision.md
```

vision.md 包含：定位 / 需求正文（用户故事与详细需求）/ 远期方向 / 演进原则 /
里程碑 / 未排期池 / 近三期排期表。

启用时按 `assets/vision-template.md`（仅参考格式）例化 `context/vision.md`，
内容由项目自行实现和改动。

## 二、运行过程

1. 接住想法：用户丢来一个想法（可能一句、可能模糊），先复述确认理解，不急着落盘。
2. 引导澄清细化：用开放、发散问题引导用户发现并澄清自己真正的需求，问清给谁用、解决什么、为什么现在做、做到什么程度算好，以及其他信息；没说清的显式标「未定」，不替用户脑补。
3. 专门调研：就需求查市场现成做法，做得足够详细；调研结果形成一份临时文档给用户过目，认可后归档进 `logs/research/`，结论吸收进正文。
4. 落盘：聊定后更新 `context/vision.md` ，只留需求现状，不留历史记录；及时写入，不攒着批量写。
5. 入池：新想法和需求未定排期前一律先进「未排期池」，不自动变当期需求；排期时由用户从池里挑。
6. 排期表滚动更新，由 agent 维护。

## 三、规范

- 只记方向、不写死方案：vision 是需求全览和方向性记录，不预设实现。
- 未定的事显式标「未定」：不得写成已定结论。
- 内容不自动成为排期需求：进入排期须走对应流程并经用户确认。

## 四、适用与边界

- **适用**：有长期规划需求的项目。
- **不管**：方案、技术选型。
