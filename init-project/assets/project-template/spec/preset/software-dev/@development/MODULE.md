# MODULE.md — 开发执行（模块规范）

> **适用范围**：当 agent 负责本模块的产出——把当期需求开发成代码 / 产物
> 时，加载并遵循本文件。项目级总纲见仓库根 `AGENTS.md`。
> 
> 本模块依赖「当期需求」（PRD，做什么）和「方案与设计」（怎么建）。
> 
> 本文件是「开发执行」模块自带的 agent 规范，随模块例化。

## 一、产物与落点

代码 / 产物落在 `workspace/source/`，按任务逐步产出，无模板可例化。

## 二、运行过程

1. 定目标：读依赖文档（当期 PRD + 方案与设计），和用户讨论定出这一期开发的目标，写入 `process/goal.md` 内。
2. 拆任务：把目标拆成任务，记录到 `process/task.md`。
3. 开发：得到用户确认后根据目标 + task.md 全权执行，当期任务一次性做完；开发过程中及时做单元测试等自测。
4. 反馈：小问题记下继续，做完统一反馈；大问题（耦合高 / 影响广 / 根基有问题）停下来回讨论。
5. 任务过程中及时更新 task 状态，任务完成后告知用户完成了哪些事，有哪些需要用户 review 的，记录进 `process/reviews/`；用户确认通过后，review 文档归档 `logs/reviews/`，goal.md 归档 `logs/goal/`。

## 三、规范

- 小问题随做随记（记在任务板），做完统一记review并反馈。
- 大问题判据：耦合高、影响面广、根基有问题——停下来回讨论。
- git 提交信息遵循 Conventional Commits（feat / fix / docs 等）。

## 四、适用与边界

- **适用**：写代码 / 产物的开发。
- **不管**：审计、发布。
