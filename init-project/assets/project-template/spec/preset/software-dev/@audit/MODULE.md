# MODULE.md — 审计（模块规范）

> **适用范围**：当 agent 负责本模块的产出——收口前做对抗排查、查工程卫生
> 时，加载并遵循本文件。项目级总纲见仓库根 `AGENTS.md`。
> 
> 本模块依赖「开发执行」和「测试与验收」（一期完整产物），以及「决策记录」（核对决策与 decisions.md 是否一致）。
> 
> 本文件是「审计」模块自带的 agent 规范，随模块例化、随模块停用。

## 一、产物与落点

审计报告（临时文档，走 review 验收）；审计完成归档 `logs/reviews/`。

## 二、运行过程

1. 自审：自己先查一遍——密钥有没有泄、有没有做需求外的东西、文档和代码
   对得上吗、决策和 decisions.md 一致吗。
2. 独立查：换一个不带开发记忆的独立 agent 再查一遍（防灯下黑）。
3. 结论：放行或打回；隐患列清单，修复后再查。

## 三、规范

- 查工程卫生，不查产品行为（产品行为归测试）。
- 对抗性：假设有问题，主动找证据推翻「做完了」的宣称。
- 根据项目特点审计，比如skill开发重点审文档、coding开发重点审代码。

## 四、适用与边界

- **适用**：交付前需要把关的产出。
- **不管**：发布。
