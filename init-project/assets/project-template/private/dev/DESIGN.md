## 开发规范

1. **版本号**：默认只升最后一位（patch）；第一位/中间位仅用户要求时升；破坏性
   变更必须用户确认并升主版本、说明迁移方案。
2. **提交信息**：`feat:/fix:/docs:/chore:/refactor: vX.Y.Z - 描述`。
3. **自动发布**：每次改动完成后自动提交、推送、tag/Release、分发/部署，不再等待
   用户明确要求（用户可关闭，记录于 `../AGENTS.md`）。
4. **文档及时更新**：开发期文档（CHANGELOG / DESIGN / TEST-REPORT）在改动完成时
   立即同步，不滞后（「改动完成即文档就绪」）。
5. **发布前必测**：检查命令 + 项目测试 + TEST-REPORT 记录（由 agent 执行）。
6. **发布前必审计**：自审 + 独立 agent 审计，发现修复后才允许发布。
7. **private 纪律**：个人/开发期文件一律进 `private/`；发布前必须先同步 private
   子 git。
8. **公开文档只写最终结果**：讨论过程、舍弃方案等开发期信息不写入公开文档；
   设计决策只记录于 `private/`。

## 测试（发布前必跑）

1. **检查命令**：`scripts/ci-check.ps1`（lint / build / test，按项目实现）。
2. **真实场景测试**（如有）：在 `../test/` 按场景清单实际执行并核对；记录到
   `TEST-REPORT.md`。
3. **明文例外（仅此一种）**：本次改动不涉及运行时文件、且用户明确确认时，测试
   结论可沿用上一版本，必须在 TEST-REPORT 注明「用户确认沿用」；禁止 agent 自行
   省略或沿用。
