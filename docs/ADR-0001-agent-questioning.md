# ADR-0001 — agent 提问与共识确认机制（决策记录）

> 状态：已接受 | 日期：2026-08-27 | Supersedes：— | Superseded by：—
> 位置说明：本工作区（母项目）无 `private/dev` 登记册，ADR 落于 `docs/`；
> 模板骨架（`project-template/private/dev/adr/`）保持不动。

## 背景（Context）

- 用户被 agent 选择题面板/问题流推着走；「回答」被当作「确认」；需求切面由 agent
  自定，用户未表态的部分从未被检查。
- `PRD-0001` 已定稿（2026-08-27，用户确认）：F1-F8 机制 + N1-N3 + 验收标准。
- 本 ADR 定案六项设计决策：新增红线形态、共识快照与阶段卡整合、反定型展示时机、
  回答重检落地、变更流程、落点文件清单。
- 用户指示：本工作区按轻量流程实施（不建 DESIGN 文件，ADR 确认后直接进入实现）。

## 决策（Decision）

1. **新增模板红线 17「提问与共识确认」**（根 `AGENTS.md`「通用红线」）：
   - 禁止调用问题面板/选择面板类结构化 UI 向用户提问（含 `request_user_input` /
     AskUserQuestionTool 类工具）；提问只在聊天/文本呈现并中止等待；
   - 聊天内可给选项与推荐（信息辅助），但**不得仅依赖选项盲目推进**；确认以用户
     自由文本明确表态为准；
   - 用户回答 = 新信息输入（非事实终点）；每次回答后内部重检问题空间；
   - 关键/风险节点展示反定型 6 项；每次提问后内部思考；
   - 每次推进前展示共识快照、用户逐项表态；达成共识 = 反定型完整展示（关键节点）
     + 用户明确确认；不得 push/诱导；
   - 确认不锁定：需求阶段内新信息直接回到反定型/共识流程；PRD 定稿后走变更流程。
2. **共识快照与阶段卡整合**：阶段卡新增「📌 共识快照（推进前确认）」区块，决策型
   推进前展示；不新增独立仪式。
3. **反定型展示时机**：决策型子阶段（PRD 定稿 / RFC 采纳 / ADR 记录 / 原型确认 /
   DESIGN 确认 / 开工 / 发布）+ 风险/不确定节点；其余提问后仅内部思考。
4. **回答重检落地**：行为规则写入 AGENTS（内部动作，不强制展示；发现假设被推翻 /
   新问题浮现时转为展示）。
5. **变更流程**：PRD 定稿后变更 = 按模板 PRD 登记册规则**开新 PRD 取代**
   （Supersedes），重新走 P1；不另建变更单机制（轻量）。
6. **落点文件**：模板根 AGENTS.md（红线 17 + P1 需求引导）、private/AGENTS.md
   （D5 + 流程提示）、PHASES.md（§5 阶段卡共识快照块 + §6 需求引导方法论）、
   docs/FLOW.md（P1 子流程 + §3.1 状态机）、docs/audit-checklist.md（新增检查项）、
   agent-rules SKILL.md（规范 17 + 工作流节 + 检查清单）+ inheritance-map.md（指纹）、
   audit-checklist-lite.md、init-project 资产镜像（sync）+ init-steps.md 覆盖；
   工作区 AGENTS.md（决策记录）+ docs/STATUS/CHANGELOG/EXP-KB。

## 后果（Consequences）

### 正面

- 回答与确认解耦；推进门槛显式化、可撤销；杜绝面板诱导；
- 反定型展示克制（仅关键/风险节点），不产生新形式主义；
- 变更流程轻量（复用 PRD 取代规则，不另建机制）。

### 负面

- 增加规范篇幅与 agent 行为约束（实现成本）；
- 聊天内提问比面板略慢（换取思考质量）；
- 需要用户主动逐项表态，交互成本略增。

## 备选方案（Alternatives）与不选原因

1. **保留问题面板、仅提示「回答≠确认」**：约束过软，无法根治诱导（不选）。
2. **完全禁止选择题（含聊天内选项）**：用户已明确「可给选项和推荐」，过度限制
   （不选）。
3. **反定型每次展示**：形式主义、对话臃肿（用户明确不选）。
4. **独立变更单机制**：与现有 PRD 取代规则重复，过重（不选）。
5. **多 agent 投票代替用户确认**（Consensus Server 模式）：内部共识≠用户共识
   （不选）。
