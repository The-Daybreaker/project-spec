## 三、发现详述

### F1（P1）check_dev_docs 字面断言与合并阶段卡骨架不匹配 —— 新项目开箱即红

- **现象**：在干净环境用当前模板初始化新项目后，立即实跑骨架脚本：
  `check_dev_docs.py` 报 `[error] STATUS.md missing 生命周期合规清单
  section/field (snapshot skeleton)` 退出码 1；`ci_check.py`（内含该检查）
  与 `pre_release_check.py` 连锁失败。
- **根因**：`check_dev_docs.py:280` 以字面字符串断言
  `("阶段卡", "任务影响清单", "要读文档清单", "生命周期合规清单")` 四块存在；
  而 v1.4.1.patch0 的阶段卡合并紧凑模块改造后，`private/dev/STATUS.md` 骨架
  的合规信息改为「合规：／✓（已完成）／⏳（待完成）」两行式，骨架全文不再
  出现「生命周期合规清单」字面串。断言与格式红线变更未同步。
- **矛盾点**：该脚本 docstring 自述「Empty registers (INDEX.md only) pass,
  so freshly initialized projects are fine」——实测与声称直接冲突；
  亦违反 `init-steps.md` 校验清单第 10/11 项（初始化后 `ci_check` /
  `check_dev_docs` 应退出码 0）。
- **影响**：任何用 ≥ 当前模板版本初始化的项目，首个开发会话的质量门禁即红，
  agent 会误判为「项目文档不合格」并做无谓修复；模板「开箱即用」核心承诺受损。
- **修复建议**（供确认）：`check_dev_docs.py` 改为断言合并格式的稳定锚点
  （如「合规：」+「✓（已完成）」/「⏳（待完成）」），保留其余三项字面断言；
  修复后重跑冒烟自检四连 + 六处副本重装 + 全链验证。

### F5（P3）`__pycache__` 混入 skill 资产镜像

- **证据**：`assets/project-template/scripts/__pycache__/` 存在 8 个 `.pyc`

  pycache = 0`），冒烟实测亦不会带入新项目（初始化复制有过滤）。
- **影响**：仅卫生问题——干扰 `diff -r` 类人工核对、增大目录体积、
  跨 Python 版本环境产生噪音差异。
- **修复建议**：`sync_template.py` 镜像时排除 `__pycache__/`（并清理现存
  残留），或在工作区 `.gitignore` 之外对资产目录定期清理；两选一即可。

## 六、根因分析与防再发机制（修复轮补充）

### 6.1 根因（F1 缺陷链，有取证时间线）

- **直接原因**：`check_dev_docs.py` 对 STATUS 用字面字符串断言「生命周期合规
  清单」；v1.4.1.patch0 把阶段卡改为合并紧凑模块后，骨架改用「合规：／✓／⏳」
  两行式，字面串消失，断言未联动。
- **取证**：`git log -S` 显示该断言引入于 `0b0b81f`（v1.4.0），当时骨架有
  独立小节「## ✅ 生命周期合规清单（D15）」，断言与骨架匹配；`051cdb2`
  （v1.4.1.patch0）改骨架格式后该字面串计数为 0，断言未改。**同期修复后
  在模板目录实跑 `check_dev_docs.py` 亦为红**——证明 v1.4.1 发布声称的
  「全链验证绿」中该检查未在真实新初始化环境实跑（沿用旧结论或非目标环境
  运行），缺陷因此漏到发布后。
- **结构性根因**：格式类红线的传播面分两层——「定义面」（PHASES / AGENTS /
  审计清单 / STATUS 骨架，发版时人工关注到）与「断言/表述面」（检查脚本字面
  断言、脚本输出文案、init-steps 清单、README / SKILL / DESIGN / LOADING
  各级摘要），后者**没有任何自动化校验覆盖**（sync 链只证文件级镜像/版本哨兵/
  红线正文指纹/文件级 init-steps 覆盖，证不了语义级过时），人工注意力也未枚举。
  F2 修复轮的全工作区 sweep 在审计 3 处之外再发现 6 处，直接验证了这一根因。
- **F5 独立根因**：`sync_template.py` 的「清理」与「复制」共用同一个跳过
  `__pycache__` 的收集函数——排除项一旦进入镜像便永不触达清理路径。
