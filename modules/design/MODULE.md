# MODULE.md — 方案与设计（模块规范）

> **适用范围**：当 agent 负责维护本模块的产出——`context/design/` 下的
> 方案文档与图纸时，加载并遵循本文件。项目级总纲见仓库根 `AGENTS.md`。
> 
> 本模块依赖用户需求。
> 
> 本文件是「方案与设计」模块自带的 agent 规范，随模块例化。

## 一、产物目录与例化

本模块的产物落在 `context/design/`，一份方案文档 + 按需图纸（图纸类型不固定）：

```
context/design/
  design.md      ← 方案文档（主体：把选路决策组织成整体方案）
  architecture   ← 架构图（常用）
  api-contract   ← 接口契约（常用）
  data-model     ← 数据模型（常用）
  key-flows      ← 关键流程走查（常用）
  prototype      ← 交互原型（常用）
  ...            ← 按需扩展：时序图 / 状态机图 / 部署图 等
```

`design.md` 是方案主体（背景与目标 / 非目标 / 方案概览 / 备选对比 /
开放问题），图纸是方案的细化——复杂处单列，简单处内嵌进 `design.md`。

启用时按 `assets/design-template.md`（格式仅供参考）例化 `design.md`；图纸按需
生成，上面列的是常用类型，不限于此，需要什么图就画什么图。

## 二、运行过程

1. 写方案：读需求和已有决策，和用户进行讨论，把这一期的选路决策组织成一份整体方案，写进 `design.md`；系统简单到脑子装得下就不写方案。
2. 画图：方案里复杂的地方，按需画图细化；常用图见上，不限于此，需要什么画什么，不强制。
3. 活文档：开发中发现方案或图纸不对，直接改（历史交给 git）。

## 三、规范

- 方案是整体、决策是散点：`design.md` 把决策组织成整体方案。
- 画完后及时向用户展示与讲解。
- 文件类型优先选择用户可直接打开查看的文件类型，比如html、markdown、jpg等常见格式，根据具体design文件所承载的内容选择最合适的文件类型，如需中间格式比如svg、canvas等，原始中间格式文件也要保留。
- 图纸按需取用，不预先生成用不到的图。

## 四、适用与边界

- **适用**：系统复杂到需要图纸的项目。
- **不管**：需求。
