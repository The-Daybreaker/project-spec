# design — 方案文档与图纸（按需取用）

> `design.md` 是方案主体，图纸是方案的细化（下面是常用五种，不限于此）。按需取用：方案简单就只写 `design.md`，复杂处再画图。方案与图纸都是活文档，开发中发现不对直接改。

## 方案文档（design.md）

把这一期的选路决策组织成整体方案，结构参考：

- **背景与目标**：为什么做、做到什么算好
- **非目标**：明确不做什么
- **方案概览**：总体怎么做（技术选型、总体思路）
- **备选对比**：比了哪些路、为什么选这条（选路过程）
- **开放问题**：没想清楚的列出来

## 架构图（architecture）

系统分几块、怎么连、数据往哪流。大产品 / 长期维护的项目需要。

## 接口契约（api-contract）

每个接口的签名、入参、出参、错误码。并行开发 / 测试的轴。

## 数据模型（data-model）

数据长什么样——表结构 / JSON schema / 字段定义。数据是核心的项目画细。

## 关键流程走查（key-flows）

挑最关键的流程画一次完整经过（谁调谁、结果传回哪）。复杂流程值得画。

## 交互原型（prototype）

界面长什么样、点了发生什么。界面项目需要。

## 其他图纸（按需扩展）

上面五种是常用图纸，不限于此——需要时序图、状态机图、部署图等时按需加，
画什么取决于方案里什么值得画。
