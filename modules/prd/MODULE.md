# MODULE.md — 当期需求（模块规范）

> **适用范围**：当 agent 负责维护本模块的产出——`context/prd/` 下的当期
> PRD 时，加载并遵循本文件。项目级总纲见仓库根 `AGENTS.md`。
> 
> 本模块依赖用户需求。
> 
> 本文件是「当期需求」模块自带的 agent 规范，随模块例化。

## 一、产物目录与例化

本模块的产物落在 `context/prd/`，每期一份，编号递增：

```
context/prd/
  PRD-0001.md
  PRD-0002.md
```

每份 PRD 包含：背景与目标 / 范围 / 非目标 / 用户故事与验收标准 / 开放问题。

启用时按 `assets/prd-template.md`（格式仅供参考）例化当期 PRD，内容由项目
自行实现和改动。

## 二、运行过程

1. 本期需求确认：和用户讨论确认需求排期，可以从 vision 的排期表取这一期要做的内容（如果有的话），先对齐「这一期做什么」。
2. 澄清细化：用开放问题聊深聊透——每条需求给谁用、解决什么、做到什么程度算好；没说清的显式标「未定」。
3. 专门调研：就需求查市场/技术现成做法，做得足够详细；调研结果形成一份临时文档给用户过目，认可后归档进 `logs/research/`，结论吸收进正文。
4. 落盘：聊定一条就覆盖更新当期 PRD 一次（历史交给 git）。
5. 更新状态：交付达标时，PRD 头部状态从「草稿」改「开发中」；开发完成时改「定格」。
6. 交付定格：这期交付后 PRD 定格，新需求新开一份 PRD。

## 三、规范

- PRD 是当期开发过程中的活文档：开发中随时改，交付即定格。
- 未定的事显式标「未定」：不得写成已定结论。
- 内容不自动成为当期需求：从排期表取，且经对话聊定。

## 四、适用与边界

- **适用**：按版本 / 期开发的项目。
- **不管**：长期方向、怎么实现。
