# RFC — 技术方案文档（方案登记册）

> 模块：项目专用（B 区私有，不进 GitHub，由 private 子 git 管理）。
> 用途：承载技术方案从草稿到采纳/否决的完整记录（怎么做、候选方案对比、为何
> 选/不选）；采纳后由 `dev/DESIGN.md` 覆盖式吸收（当前设计），本目录保留方案
> 历史。

## 使用规则（强制）

1. **新建方案**：`RFC-<NNNN>-<slug>.md`，头部注明依据 `PRD-XXXX`（PRD 须已定稿）。
2. **草稿阶段可编辑**；提交评审（状态=评审中）后候选对比冻结。
3. **评审**：用户拍板 → 状态=已采纳 / 已否决；已采纳的架构级方案 → 写
   `ADR-XXXX`（见 `adr/INDEX.md`）→ `dev/DESIGN.md` 覆盖式吸收；已否决保留为
   历史，可被新 RFC 取代。
4. **方案演进**：新 RFC 取代旧 RFC（新 RFC 头部 `Supersedes: RFC-XXXX`；旧 RFC
   仅状态元数据改为「已废弃（由 RFC-XXXX 取代）」，正文不动）。
5. **正文冻结**：已采纳/已否决后正文不可改（仅状态元数据可改）。
6. **调研**：现状与调研节只写 2-3 行摘要，完整调研见 `RESEARCH-XXXX`。

## 状态机

```
草稿 → 评审中 → 已采纳 / 已否决 → 已废弃（被新 RFC 取代）
```

- 状态变更权限：评审中→已采纳/已否决 必须**用户拍板**；任何→已废弃 必须**用户确认**。

## 编号

- `RFC-0001` 起，4 位前缀零；文件名 `RFC-0001-<slug>.md`；编号**永不重用**。
