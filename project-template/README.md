# 通用项目模板 v3

一套以 agent 为第一读者的通用项目模板。**结构是地基，工作流是 spec**：
七件套骨架（冷启动、任务板、人机交流三件套、git 卫生）保证任何项目最低
限度可运转；文档种类、流程编排、仪式轻重全部由 spec 包声明——spec 是
模子，context 是模子出的件；空 spec 的项目以地基形态轻装运转。

## 给用户的规范（与 agent 协作，最好这样做）

> 本节为**用户维护区**：内容由用户本人增删与润色，agent 只做格式整理。

1. **使用正向提示词**：不要使用“不要xxx”这样的提示词，越是强调不要，模型越会记住。而是采用正向描述，“把xxx改为xxx”、“只需要xxx”。
2. **提需求一句话就够**：说清要什么、给谁用即可，agent 会追问；不成熟
   的想法直接丢 `process/inbox/`，不用组织语言，agent 会展开和归类。
3. **立项类话题先调研**：聊新项目、新功能时，agent 会先查现成参考再
   动手——配合这一步，「先调研再立项」，别急着从零造轮子。
4. **看进度直接问**：直接问 agent，或看 `process/task.md`；`process/`
   只放活的，扫一眼就是全部待办，不用翻历史。
5. **换新会话不用交代背景**：新开对话直接说事，agent 冷启动会自己读
   盘恢复状态；对话中断也不丢状态，你什么都不用做。
6. **及时批复 pending**：`process/pending/` 是 agent 等你拍板的决策，
   每个都带选项、倾向与不决策的后果；批复越及时阻塞越少，拖过 14 天
   会被标过期。
7. **验收看 review request**：`process/reviews/` 五节里重点看「如何
   验证」和「风险与不确定」；批准、返工、部分接受，回一句话即可。
8. **agent 停下来时是真需要你**：不可逆操作、写入交付物、结构变更——
   这些确认不要略过；除此之外低风险改动它会先做后说，不必事事点头。
9. **纠错直说**：哪里不对直接指出，agent 会直接改，不辩解、不留痕迹。
10. **密钥与个人信息不入库**：`.env`、`*.key` 等常见密钥文件
    `.gitignore` 已自动拦截，但口令、密钥、个人信息也别写进会被提交
    或对外发布的内容；项目默认全私有，公开 / 推送属不可逆操作，agent
    动手前会找你确认。
11. **删除的东西先去 `_trash/` 找**：对话内删除都先进项目本地的临时
    删除区（已进 .gitignore），任务结束才整体清走；误删了去那里找，
    确需永久删除 agent 会先问你。
12. **状态文件交给 agent 维护**：任务板 / pending 状态不手工改，你的
    想法走对话或 inbox。
13. **spec 包启停找 agent**：引入 / 停用 spec 包只需说一声，agent 会更新
    注册表；你不手工增删包内文件。

## 快速开始

1. 复制本模板七件套到新项目目录（不含 `_trash/`、`.git/`）。
2. 首次对话让 agent 冷启动（它会读 AGENTS.md 恢复上下文），对齐项目
   背景与目标，task.md 开始记录。
3. 需要文档体系 / 工作流时，按 `spec/AGENTS.md` 的指引从云端模块库拉取
   spec 包（如 software-dev：8 模块）与构建规则；
   没有 spec，项目照常运转。
4. （可选）启用推送前密钥门禁：`git config core.hooksPath .githooks`，
   之后每次 push 自动扫描密钥与个人信息（`scripts/scan_secrets.py`）；
   正常出现的本机标识按需加进 `scripts/scan_secrets.ignore` 排除
   （该文件已进 .gitignore，内容不会提交）。

## 目录速览

| 目录           | 放什么                                              |
| ------------ | ------------------------------------------------ |
| `spec/`      | 模子：spec 包与构建规则按需云端拉取（指引见 `spec/AGENTS.md`） |
| `context/`   | 模子出的件：PRD / ADR……种类与有无由 spec 决定，零固有件 |
| `process/`   | 运行时：task.md + inbox / pending / reviews 三件套，只放活的 |
| `workspace/` | 对外产出：source（源产物）+ delivery（交付物）；发布的是这里           |
| `logs/`      | 固有历史：三件套归档 + 讨论记录（可选件）                           |

详细协作协议（冷启动链、三件套协议、规范）见 `AGENTS.md`。
