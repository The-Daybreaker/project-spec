## 项目怎么运转：五个阶段

项目按 5 个大阶段串行推进，每次只专注一个：

| 阶段 | 做什么 | 你要做什么 |
|---|---|---|
| **P1 需求** 🔵 | 听懂你要什么，澄清需求，产出需求文档 | **确认需求**（不点头不往下走） |
| **P2 方案** 🔵 | 候选方案对比，产出设计/原型 | **拍板方案/原型/设计** |
| **P3 开发** 🟢 | 按方案实施 | 看阶段卡即可，不反对就继续 |
| **P4 审计验证** 🟢 | 自检 + 测试 | 看阶段卡即可 |
| **P5 交付发布** 🟠 | 提交、发布、沉淀经验 | **发布动作单独确认** |

- 🔵 决策型阶段：助手会**停下来等你确认**；
- 🟢 执行型阶段：助手展示阶段卡后，你不反对就继续（随时可叫停）；
- 🟠 发布属高风险，单独确认。

小事情可以裁剪：启动时或执行中，你可以决定跳过某些允许跳过的环节（比如小需求
跳过方案阶段）。每次裁剪助手都会向你确认，并记下「跳了什么、为什么能跳、用什么
代替」——裁剪规则详见 `private/dev/PHASES.md`「阶段契约」。

## 阶段卡怎么看

每完成一个阶段/子阶段，助手会展示一张**阶段卡**，看三样东西：

1. **阶段线**：该阶段全部节点一行排开，当前节点**加粗**——走到哪、还剩多少，
   一目了然；
2. **合规两行**：`✓ 已完成` 一行、`⏳ 待完成` 一行——⏳ 里有什么，就说明助手
   还没做哪一步；
3. **共识卡**（决策型阶段推进前）：助手列出它的理解、缺口、疑问，等你逐项表态
   才推进。

格式细节见 `private/dev/PHASES.md` §5。

## 中断了怎么恢复

对话中断或压缩，你什么都不用做——助手会读 `private/dev/STATUS.md` 进度快照
自动恢复，然后展示阶段卡让你确认进度对不对。

## 开发与发布（简介）

- **协作规范**：助手怎么接手、开发怎么走、哪些红线不能碰——见根 `AGENTS.md`；
- **开发前门禁**：较大的需求先出需求文档（PRD）/ 方案文档（RFC）/ 决策记录
  （ADR），定稿后才实施；
- **先出图再确认**：涉及界面/架构/流程的改动，助手先出图给你看，确认后才动手；
- **先调研再立项**：讨论立项思路时，助手会先调研现成参考；
- **版本与发布**：版本号以 `version.json` 为唯一事实来源，发布前检查由脚本
  自动把关（`scripts/pre_release_check.py`）；
- **归档**：项目停止开发时，按根 `AGENTS.md`「项目归档/退役」流程走；
- 人类贡献者的协作约定：见 `docs/CONTRIBUTING.md`。

## 常见问题

- **「助手现在在哪？」** → 直接问，助手会展示阶段卡（或打开
  `private/dev/STATUS.md`）。
- **「这个阶段算完成了吗？」** → 看阶段卡状态，且合规两行没有待完成项。
- **「能不能跳过阶段？」** → 小需求可裁剪（须与助手确认并声明），详见阶段契约。
- **「历史记录哪去了？」** → 进度快照只存最新状态；历史由 git 承担
  （`git log`）。
