# FLOW — 项目运转流程与状态机总图

> 模块：混合（【通用】= 阶段体系/动作状态机可随模板升级；【项目专用】= 本项目实例）。
> 用途：穷举项目运转的**每种动作的链路**与**每个动作的状态机**；「每个阶段单独运行时的
> 流程（含阶段外行为）」的单一真相，配 `private/dev/PHASES.md`（阶段模块权威定义）使用。

## 0. 双维度模型

- **主流程维度**：P1-P5 五阶段**串行**，一次只专注一个，严禁跨阶段；
- **贯穿维度**：文档维护/STATUS 落盘/git 提交/经验沉淀/审计/删除归档等**不占阶段**，
  任何阶段内都可触发，每次走各自状态机并落盘。
- 阶段切换：🔵 决策型（P1/P2）→ 展示阶段卡 + **用户确认**后放行；🟢 执行型（P3/P4）→
  展示阶段卡，无反对即继续；P5 发布动作**另行确认**（红线 2）。

```mermaid
flowchart LR
    U[用户意图] --> P1[P1 需求 🔵决策<br/>01-05]
    P1 -->|阶段卡+确认| P2[P2 方案 🔵决策<br/>06-09]
    P2 -->|阶段卡+确认| P3[P3 开发 🟢执行<br/>10-11]
    P3 -->|阶段卡| P4[P4 审计验证 🟢执行<br/>12-13]
    P4 -->|阶段卡| P5[P5 交付发布 🟠发布须确认<br/>14-16]
    P5 -->|阶段卡+发布确认| D[阶段收尾]
    U -.S档直达.-> P3
```

## 2. 每阶段子流程（阶段内子阶段 + 阶段外行为挂载点）

> 每个子阶段：干活 → 产物 → 质量校验 → 落盘 STATUS → 展示阶段卡 → git 提交。
> 🔵 决策型子阶段等用户点头；🟢 执行型子阶段展示后无反对即继续。

### P1 需求（01-05，决策型）

```mermaid
flowchart LR
    A[倾听意图] --> B[需求引导提问<br/>复述+开放问题·禁抛选项]
    B --> C[回答重检+反定型展示<br/>关键/风险节点]
    C --> D[共识快照+逐项确认]
    D --> E[调研 GitHub 红线13]
    E --> F[PRD 草稿 03]
    F --> G[PRD 评审 04<br/>图随稿展示确认]
    G --> H[PRD 定稿 05 🔵<br/>INDEX 同步+门禁]
    H --> I{用户确认放行?}
    I -->|是| J[移交 P2]
    I -->|否| F
```

### P2 方案（06-09，决策型）

```mermaid
flowchart LR
    A[读定稿 PRD] --> B[RFC 草稿 06]
    B --> C[RFC 评审 07 🔵采纳/否决]
    C --> D[ADR 记录 08 🔵]
    D --> E[原型确认 🔵<br/>prototype/ 先出图再确认]
    E --> F[DESIGN 吸收 09 🔵]
    F --> G{用户确认放行?}
    G -->|是| H[移交 P3]
    G -->|否| C
```

### P3 开发（10-11，执行型）

```mermaid
flowchart LR
    A[确认开工 10] --> B[实施 11 按 DESIGN 分解子步骤]
    B --> C{每个子步骤完成}
    C -->|落盘+阶段卡+提交| B
    C -->|PRD=已实现| D[移交 P4]
```

### P4 审计与验证（12-13，执行型）

```mermaid
flowchart LR
    A[自动审计 12<br/>自审→独立子agent] --> B{发现问题?}
    B -->|是| C[修复+复检]
    C --> A
    B -->|否| D[验证 13 ci_check+测试]
    D --> E[TEST-REPORT 记录]
    E --> F[移交 P5]
```

### P5 交付发布（14-16）

```mermaid
flowchart LR
    A[展示与提交 14] --> B[发布 15 🟠另行确认<br/>版本递增→文档就绪→private同步→tag/Release]

    C --> D[阶段收尾]
```

## 3. 动作状态机（穷举动作链路）

### 3.1 需求引导（P1 内嵌）

```mermaid
stateDiagram-v2
    [*] --> 倾听意图
    倾听意图 --> 引导提问: 复述+开放问题（禁面板 红线17）
    引导提问 --> 回答重检: 用户回答=新信息输入
    回答重检 --> 反定型展示: 关键/风险节点
    反定型展示 --> 共识快照: 用户确认=达成共识
    共识快照 --> 调研: 红线13
    调研 --> 需求明确
    需求明确 --> 引导提问: 新信息出现（定稿前可回审）
    需求明确 --> [*]
```

### 3.2 发版

```mermaid
stateDiagram-v2
    [*] --> 待发版
    待发版 --> 版本递增: bump_version（minor/major须确认）
    版本递增 --> 文档就绪: CHANGELOG/文档同步
    文档就绪 --> private同步: pre_release_check
    private同步 --> 提交推送
    提交推送 --> tag与Release: 手动或CI
    tag与Release --> 已发布
    已发布 --> [*]
```

### 3.3 同步模板（仅模板母项目；本项目升级见 `docs/UPGRADE.md`）

```mermaid
stateDiagram-v2
    [*] --> 待同步
    待同步 --> 镜像同步: 改动 project-template/
    镜像同步 --> 校验: sync_template.py
    校验 --> 已同步: 全链通过（版本/指纹/覆盖/副本）
    校验 --> 失败拦截: 任一不过
    失败拦截 --> 待同步: 修复后重跑
    已同步 --> [*]
```

### 3.4 文档更新（贯穿，红线 12）

```mermaid
stateDiagram-v2
    [*] --> 当前有效
    当前有效 --> 待更新: 决策/流程变更
    待更新 --> 更新中: 覆盖式修改正文（禁历史标注）
    更新中 --> 待回读: 写入完成
    待回读 --> 当前有效: 回读校准通过
    待回读 --> 更新中: 修正重写
```

### 3.5 STATUS 快照更新（贯穿）

```mermaid
stateDiagram-v2
    [*] --> 当前快照
    当前快照 --> 待落盘: 子阶段完成/进度变化
    待落盘 --> 覆盖更新: 覆盖式写入最新状态
    覆盖更新 --> 已提交: git commit（主+私）
    已提交 --> 当前快照
```

### 3.6 审计（P4，红线 3）

```mermaid
stateDiagram-v2
    [*] --> 待审计
    待审计 --> 自审
    自审 --> 独立审计: 通过（推荐独立子agent）
    独立审计 --> 修复: 发现问题
    修复 --> 独立审计: 复检
    独立审计 --> 审计通过
    审计通过 --> [*]
```

### 3.7 经验沉淀（贯穿，红线 9）
