# USER-GUIDE — {{PROJECT_NAME}} 阶段流程简明指南（面向人）

> 模块：混合（【通用】= 阶段体系/阶段卡可随模板升级；【项目专用】= 本项目实例）。
> 读者：项目主人/使用者。**目的：防止遗忘**——随时查「项目有几个阶段、每个阶段做什么、
> 产出什么、你什么时候需要确认、阶段卡怎么看」。
> 阶段权威定义（含流程图与状态机）见 `private/dev/PHASES.md`。

## 1. 一句话

本项目按 **5 个大阶段**串行运转，每个阶段有明确的输入、任务、产物和完成标志；
每次只专注一个阶段，阶段内再分子阶段细化；每个阶段/子阶段完成时你会收到一张
**阶段卡**，告诉你进度、下一步，以及 agent 有没有按规范走完生命周期。

**设计原则**：分阶段的目的是为了专注，分子阶段的目的是为了细化——你既能专注当前
大阶段，也能了解阶段内执行进度。

## 2. 五个阶段一览

| 阶段 | 做什么 | 产物（交付物） | 你要做什么 |
|---|---|---|---|
| **P1 需求** 🔵 | 澄清需求 → 调研 → 写 PRD → 评审定稿 | 需求文档 PRD + 调研记录 | **确认需求**（决策型，必须你点头） |
| **P2 方案** 🔵 | 候选方案 RFC → 决策 ADR → 原型 → 设计 DESIGN | 方案文档 + 架构决策 + 原型 + 设计文档 | **确认方案/原型/设计**（决策型） |
| **P3 开发** 🟢 | 按设计实施 | 代码 + 文档就绪 | 看阶段卡，不反对即继续 |
| **P4 审计验证** 🟢 | 自动审计 → 测试验证 | 审计结论 + 测试报告 | 看阶段卡，不反对即继续 |
| **P5 交付发布** 🟠 | 展示提交 → 发布 → 沉淀汇报 | commit/tag/Release/经验 | 发布时**单独确认** |

- 🔵 决策型阶段/子阶段：agent 会**停下来等你确认**才继续；
- 🟢 执行型阶段/子阶段：agent 展示阶段卡后**无反对即继续**（你随时可叫停）；
- 🟠 发布动作单独确认（红线 3：发布/推送属高风险）。

## 3. 阶段卡怎么读（每次 review 就看它）

实质回复 / 阶段完成 / 收尾时，agent 会展示一张**合并紧凑阶段卡**，就一个模块：

1. **标题（含状态）**：哪个阶段，进行中还是已完成；
2. **横置阶段线**：该阶段全部节点一行排开，当前节点**加粗**——一眼看到「走到
   哪、还剩多少」；
3. **合规两行**：`✓ 已完成` 一行、`⏳ 待完成` 一行，涵盖文档同步 / 状态落盘 /
   git 提交 / 质量校验 / 红线遵循等七项——**⏳ 里有什么，就说明 agent 还没做哪步**；
4. 决策型阶段推进前，阶段卡附 **📌 共识卡**（认知基线 / 缺口 / 质疑 / 推进结论），
   须你逐项表态才推进。

> 每次 review 只看当前阶段/子阶段的产物即可，量小、专注。格式细节见
> `private/dev/PHASES.md` §5。

## 4. 你什么时候需要介入

| 时机 | 你的动作 |
|---|---|
| P1 需求定稿 / P2 方案（RFC/ADR/原型/DESIGN）确认 | 点头或提出修改 |
| 阶段卡合规行有 ⏳ 待完成项 | 要求 agent 补做 |
| 任何阶段你看到进度不对 | 直接叫停，让 agent 回到当前阶段 |
| P5 发布 | 单独确认版本递增与发布 |
| 任务中断/新对话 | 什么都不用做——agent 按 STATUS 快照自动恢复 |

## 5. 恢复机制（中断/压缩后）

agent 恢复顺序：读 AGENTS → 读 STATUS 快照（看阶段卡判断进度）→ 按「要读文档清单」
逐份读 → 展示阶段卡继续。**你只需要确认阶段卡显示的进度是否正确即可。**

## 6. 阶段与文档（披露隔离）

每个阶段只专注自己的文档，历史默认不读——所以你看文档时也可以只关心当前阶段：

| 阶段 | 看什么文档 |
|---|---|
| P1 | `private/dev/prd/`、`research/` |
| P2 | `private/dev/rfc/`、`adr/`、`prototype/`、`DESIGN.md` |
| P3 | `DESIGN.md` + 对应 PRD（只读） |
| P4 | `TEST-REPORT.md`、审计结论 |
| P5 | `CHANGELOG.md`、发布产物 |

## 7. 常见问题

- **「agent 现在在哪？」** → 直接问，agent 会展示阶段卡（或打开 `private/dev/STATUS.md`）。
- **「这个阶段算完成了吗？」** → 看阶段卡状态：⏳ 进行中 / ✅ 已完成，且合规行
  没有待完成项。
- **「我能不能跳过阶段？」** → S 档小需求可 P1 简化直达 P3；其余按需与 agent 确认。
- **「历史记录哪去了？」** → STATUS 只存最新状态；历史由 git 承担（`git log`）。
