# TEST-MAP — 测试台账（测试在保护什么）

> 模块：全通用（模板自带、可随模板升级）。
> 用途：**一处看清每个测试/脚本在保护什么、能测出什么、测不出什么（盲区）**。
> 每个测试按三要素说明（意图/展示/验收）；脚本增删时同步更新本台账。

<!-- FACT:test-map -->

- **动机**：测试不可见导致「不知道在测什么、不敢信」；给每个测试附上「保护的
  规范 + 能测出的问题 + 盲区」，保护网变得可核验，缺口也一目了然。

| 测试/脚本 | 断言什么（意图） | 能测出什么 | 盲区（测不出什么） | 展示/验收 |
|---|---|---|---|---|
| `scripts/check_dev_docs.py` | 登记册一致性：编号连续、状态机、INDEX 与正文一致、STATUS 阶段卡锚点、ROADMAP 对齐 | 登记册混乱、索引正文不一、快照锚点缺失 | 文档内容的语义对错 | 退出码 + 逐项报告 |
| `scripts/check_consistency.py` | 漂移免疫门禁：事实唯一家、引用摘要限长、正文指纹、注入一致 | 多家重复、变相完整展开、正文偷改、未登记锚点 | 不打锚点的换词复述（靠审计人工补） | 拦截清单 + 待安家提示 |
| `scripts/pre_release_check.py` | 发布一键门禁：私有区同步且无远端、版本一致、泄漏扫描、检查命令非占位、文档一致 | 私有区未同步就发布、版本漂移、密钥文件、占位遗留 | 业务逻辑的功能缺陷 | 退出码 + 逐项报告 |
| `scripts/scan_secrets.py` | 高危凭据零容忍 + 个人信息扫描（--check/--strict/--history） | 密钥入库；内容与全历史中的本机路径/用户名 | 规则未列的低风险敏感表述（须人工复核） | 命中清单；门禁退出码 |
| `scripts/scan_defensive.py` | 红线 17 验收：提交信息辩护性措辞硬拦；注释/文档出复核清单 | 为「未做/不做的事」补写的说明 | 语境化的委婉辩护 | 硬拦 + 人工复核清单 |
| `scripts/ci_check.py` | lint/build/test 统一入口（按项目实现；默认含登记册校验 + 辩护措辞扫描） | 取决于项目实现 | 未实现时只是占位（发布门禁会断言非占位） | 退出码 |
| `scripts/trash.py` | 删除走可恢复路径（临时删除区整体进回收站） | —（动作脚本，不做断言） | 忘记用它（由审计清单人工核对） | 执行输出 |
| `scripts/bump_version.py` | 版本递增按同步表联动各版本文件 | 版本文件漏联动 | 文档里的版本引用遗漏（靠审计与登记册校验） | 执行输出 |

- **组合关系**：发布时 `pre_release_check.py` 串起上述门禁；各脚本盲区由审计
  清单（`docs/audit-checklist.md`）与独立审计（人工视角）补位。
- **持续验证**：母项目发版前另有开箱冒烟（初始化临时项目 + 骨架脚本自检），
  保证新项目首跑即绿。
