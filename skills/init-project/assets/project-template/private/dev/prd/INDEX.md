# PRD — 需求文档（需求登记册）

> 模块：项目专用（B 区私有，不进 GitHub，由 private 子 git 管理）。
> 用途：承载每个需求从提出到定稿 / 实现 / 废弃的完整记录；本目录即**需求登记册
> （backlog）**：草稿=需求池、已定稿=排期、已实现=完成、已废弃=放弃/被取代。
> 新建需求/需求变更时先读本文件「使用规则」，再按「模板骨架」创建文档。

## 使用规则（强制）

1. **新增需求**：新建 `PRD-<NNNN>-<slug>.md`（编号递增、不重用），并在下方
   索引表登记（插入对应「状态 + 优先级」分组顶部；已实现/已废弃沉底）。
2. **需求变更**：
   - 未定稿（草稿）：直接编辑正文（尚未产生历史，允许覆盖）；
   - 已定稿：**开新 PRD 取代**（新 PRD 头部注明 `Supersedes: PRD-XXXX`；旧 PRD
     仅状态元数据改为「已废弃（由 PRD-XXXX 取代）」，正文不动）。
3. **定稿门禁**：状态=已定稿 且 以下字段齐全、用户明确确认：背景与目标 / 用户与
   场景 / 需求范围 / 验收标准 / 不在范围 / 优先级。**未定稿不进入方案设计**
   （RFC / ADR）。
4. **优先级**：P0 紧急/阻塞（当前版本必须）→ P1 高（近期排期）→ P2 中（计划内）
   → P3 低/待定（想法池）；属元数据，可随时更新，不违反正文冻结。
5. **实现**：实施完成后状态=已实现 + 填「实现版本」，CHANGELOG 对应版本条目引用
   `PRD-XXXX`。
6. **正文冻结**：定稿后正文（背景/范围/验收等）不可改；仅状态、优先级、实现版本
   等元数据可改。
7. **调研**：涉及红线 13 立项调研时，正式调研写 `RESEARCH-XXXX`（见
   `research/INDEX.md`），本文件「调研结论」只写 2-3 行摘要 + `详见 RESEARCH-XXXX`。

## 状态机

```
草稿 → 已定稿 → 已实现
  └→ 已废弃（放弃，或被新 PRD 取代）
```

- 状态变更权限：草稿→已定稿、任何→已废弃 必须**用户确认**；已定稿→已实现 由
  agent 实施完成后**自动**更新。

## 编号

- `PRD-0001` 起，4 位前缀零；文件名 `PRD-0001-<slug>.md`；编号**永不重用**。
- 编号跨版本持续增长、不重置（与版本号无关）。
