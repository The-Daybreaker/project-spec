# prototype — 页面原型 / 设计稿（B 区私有）

> 模块：项目专用（B 区私有，不进 GitHub，由 private 子 git 管理）。
> 用途：承载**界面/交互改动**的可视化产物——页面原型与 UI 设计稿。与 `DESIGN.md`
> 区分：`DESIGN.md` 是技术/方案设计文档（存 RFC/ADR 结论），本目录是 UI 设计产物
> （线框 / 交互原型 / 高保真稿 / 设计文件）。
> 轻量目录：无状态机、无编号登记册；随设计阶段使用，关键交互结论吸收进
> `DESIGN.md`（正文=当前状态，不重复维护）。

## 使用规则（强制）

1. **何时必出**：涉及**用户界面/交互**改动时产出（M/L 档；S 档最小改动或纯后端
   无界面项目可声明跳过并在 STATUS 记录理由）。
2. **一文件一原型**：每个页面原型/设计稿单独一个文件（`PROTO-XXXX-<slug>.md` /
   `.html` / `.svg` / `.png` 均可，推荐内嵌 Mermaid 或直接放图），文件名自解释。
3. **展示确认**：产出后向用户展示，**获确认后才进入实施**（`../../AGENTS.md` 开发
   工作流「可视化确认」）；未确认不实施。
4. **结论吸收**：原型评审确认的关键交互、跳转、状态结论，覆盖式写入
   `DESIGN.md`，不在本目录重复维护（单一真相）。
5. **不写历史**：原型被推翻/废弃时直接删除（走 `_trash/` →
   `../../scripts/trash.py`），不留「已废弃」标注（正文=当前有效状态，红线 13/16）。

## 与四登记册的关系

- **流程图**（业务/用户流程、时序、状态）与**架构图**（组件/数据流/部署）随所属
  `prd/` `rfc/` `adr/` 目录同目录存放（Mermaid/SVG 单文件），**不放本目录**；
  本目录只放**页面原型/设计稿**。
