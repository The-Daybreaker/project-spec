# design/ — 设计契约文件夹

> 模块：【通用】= 目录约定；【项目专用】= 契约内容。
> 用途：存放设计契约（协作面、审核面）。`../DESIGN.md` 是设计总览与契约索引；
> 详细契约放本文件夹。

## 契约文件（适用必做 / 不适用须声明；声明落设计总览，不建空文件）

| 文件 | 内容 | 何时必做 |
|---|---|---|
| `architecture.md` | 架构设计（模块划分、交互方式） | 多模块/多服务时 |
| `interface-contract.md` | 接口契约：接口清单（大白话）+ 场景映射表（审核面）+ 错误情况 + 使用示例 | 有接口时 |
| `data-model.md` | 数据设计：实体/字段/关系/状态 | 有持久化数据时 |
| `security.md` | 安全设计：权限模型/敏感数据处理 | 有登录/权限/敏感数据时 |
| 可选：`openapi.yaml` / `*.proto` / 类型定义 | 技术接口文件（供机器使用） | 项目按技术栈自选 |

## 规则

- **审场景不审技术**：接口契约的场景映射表写给用户审核，只问两个问题——
  「场景漏了吗？每个场景的结果是我想要的吗？」；技术细节不进审核面；
- **冻结**：接口契约经用户确认场景映射后冻结（确认状态标注在文件头）；改契约
  = 改约定，必须重新经用户确认；
- **验收联动**：场景编号（S1…）与测试报告用户验收区用例一一对应，测试验证
  接口实际行为与契约一致（审核有漏，测试兜底）；
- **裁剪声明**：不适用的契约不建空文件，在 `../DESIGN.md`「设计总览与契约
  索引」声明「不适用（原因）」——省略可见，而非静默缺失。
