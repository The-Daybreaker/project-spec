# 审计清单（精简版，audit-checklist-lite.md）

> 用途：实施完成后的自动审计。**自审**（实施者逐项核对）与**独立审计**（独立
> agent / 独立会话，只看 diff 与本清单）共用。逐项标注 ✅ / ❌ / N/A；❌ 必须附说明
> 并修复。

## 1. 需求与计划对齐

- [ ] 需求已复述，方案要点已列明，且获得用户明确确认（未确认不实施）
- [ ] 提问与共识确认合规（规范 18）：未调用问题面板/选择面板；选项仅信息辅助；
      回答后输出重检行；硬触发节点展示共识卡四项并获用户逐项表态；无 push/诱导
- [ ] 立项类话题已做 GitHub 调研并提醒「先调研再立项」（如适用）
- [ ] 改动范围与确认方案一致（无夹带未确认的改动）
- [ ] 高风险操作（破坏性变更、永久删除、发布/推送）已征得同意

## 2. 实现正确性

- [ ] 边界情况与错误处理已考虑（输入校验、失败路径、回退）
- [ ] 无死代码/调试残留；无重复实现
- [ ] 无意外删除或误改（diff 中无「路过修改」）

## 3. 文档/内容同步

- [ ] 受影响文档已同步更新（正文 = 当前有效状态，无历史标注残留）
- [ ] 发现过时内容已立即修复；状态文档（进度）已校准
- [ ] 本轮候选经验已写入 EXPERIENCE-TO-KB（如有）

## 4. 红线合规

- [ ] 三要素（规范 1）：本次涉及的红线/要求均有意图、展示面与验收面
- [ ] 删除均走可恢复路径（临时删除区 → 回收站）；无绕过工具的永久删除
- [ ] 上下文压缩/新对话后已重读规范与进度文档
- [ ] 重要写入已回读校验（多文件并行编辑后整篇回读抽查）
- [ ] 创建前做过相似检查
- [ ] 未破坏用户未提交的改动；无对共享分支的 force push
- [ ] 无密钥/凭据/个人专属信息进入公开内容（搜索 `.env`、`key`、`token`、
      `password` 等字样于 diff）；私有区未设远端、未打包（例外已走
      检查→报告→用户确认）
- [ ] 无「为未做之事补写说明」类表达（标题/提交信息/PR/注释/文档中无「已移除
      多余 X」「为什么不需要 X」等辩护性文字）

## 5. 验证与交付

- [ ] 产出自测可运行、关键内容齐全、无运行时数据/密钥混入
- [ ] 检查/测试通过且有记录（或「用户确认沿用」并注明）
- [ ] 汇报附完成检查清单、回退方式
